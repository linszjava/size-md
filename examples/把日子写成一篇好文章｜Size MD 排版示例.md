# 把日子写成一篇好文章

一次从清晨出发的写作练习，也是 Size MD 的完整排版示例。

一篇文章的气质，藏在许多细节里：标题与正文之间的距离，引用旁边那条安静的线，代码的留白，以及一小块恰到好处的颜色。我们不妨以一个普通的周末为线索，看看文字如何变成一篇值得读完的文章。

**阅读提示：**你可以切换「主题」，比较同一篇文章的不同面貌；也可以打开公众号预览，或者导出 PDF 检查分页。

## 01 / 给清晨留一段空白

早上七点，窗外刚有一点光。水壶还没有烧开，桌上只放着一本书、一支笔和昨天没有写完的几行字。这时候不必急着打开消息列表，先把脑海里最清晰的那个念头留下来。

**加粗适合标记重点**，*斜体适合轻声补充*，而 ***加粗与斜体组合*** 可以表达更强的语气。写作时也难免改变主意：~~今天必须写完五千字~~，不如先认真写好一个段落。

> 好的排版，不会抢走文字的声音。
>
> 它只是让每一次停顿、转折和强调，都发生在恰当的位置。

正文需要节奏。短句让人停下来。稍长一点的句子，则把环境、动作与感受慢慢铺开，让读者有时间进入你正在讲述的世界。两者交替，文章才不会显得匆忙，也不会过于拖沓。

### 从一个具体的画面开始

不要急着写“今天很美好”，试着写：阳光落在木桌边缘，杯子上方升起一条细细的白雾。抽象的感受，往往可以由具体的细节自然带出来。

#### 观察：先看见，再判断

看看物品的形状、光线的方向和空间里的声音。这些都可以成为段落的起点。

##### 记录：保留尚未成熟的句子

灵感不一定是一整段话。有时只是一个词、一种颜色，或者一个还没有答案的问题。

###### 编辑：最后再决定留下什么

这一行用六级标题，方便比较主题中不同层级的字号、粗细与间距。

## 02 / 用颜色给文字一点提示

颜色适合帮助读者发现重点，而不必成为整篇文章的主角。

## 03 / 把想法整理成可以执行的步骤

### 一张简单的准备清单

- 找一个能安心坐下来的地方。
- 准备一杯水，关掉暂时不需要的提醒。
- 打开一份新的文档。
  - 先写下暂定标题。
  - 记住三个关键词。
  - 留出一个可以随时补充的段落。
- 给自己二十分钟，开始写作。

### 一次完整的写作流程

1. **收集素材**：记录场景、对话和细节。
2. **确定线索**：回答“这篇文章想带读者去哪里”。
3. **写出初稿**：先让内容连贯起来。
4. **调整结构**：把最重要的内容放在容易看见的位置。
5. **检查排版**：确认标题、图片、表格和代码都易于阅读。

### 发布前的小检查

- [x] 标题能够表达文章的主要内容。
- [x] 段落之间留有舒适的呼吸空间。
- [ ] 检查所有链接是否可以打开。
- [ ] 在手机宽度下检查表格与图片。
- [ ] 导出 PDF，看看分页是否自然。

> 小提示：列表适合呈现并列信息，编号适合表达顺序。两者并不需要在每个段落里都出现。

## 04 / 用表格比较，而不是让读者记忆

下面是一份虚构的周末安排。表格中分别使用左对齐、居中和右对齐，方便观察主题的处理方式。

| 时段 | 安排 | 状态 | 预计分钟 |
| :--- | :---: | :---: | ---: |
| 清晨 | 散步与观察 | 已完成 | 30 |
| 上午 | 写作初稿 | 进行中 | 60 |
| 午后 | 阅读与摘记 | 待开始 | 45 |
| 傍晚 | 修改与排版 | 待开始 | 25 |

一张更长的表格，可以测试中文换行与单元格内的强调：

| 内容类型 | 适合表达什么 | 使用建议 |
| --- | --- | --- |
| 普通段落 | 场景、故事、完整的思路 | 保持自然叙述，不必每句话都强调 |
| **加粗文字** | 结论、关键词、行动提示 | 一段里只强调真正重要的部分 |
| 引用块 | 摘录、旁白、补充观点 | 保持简洁，让它与正文形成节奏 |
| `行内代码` | 命令、变量名、文件名 | 使用等宽字体，便于识别 |
| 表格 | 同一维度下的多项比较 | 手机上检查列宽和换行 |

点击表格中的单元格，还可以试试表格工具栏里的增加行列、对齐和尺寸调整。

## 05 / 让代码也保持可读

如果文章里需要提到文件名，可以写成 `notes.md`；如果需要解释变量，可以使用 `draft.title`。行内代码应当和普通文字保持协调，而不是挤占整段的注意力。

### JavaScript：把一句话变成记录

```javascript
const draft = {
  title: "把日子写成一篇好文章",
  tags: ["写作", "生活", "排版"],
  published: false,
};

function describe(article) {
  // 让每一个字段都保持清楚的含义。
  return `${article.title} · ${article.tags.join(" / ")}`;
}

console.log(describe(draft));
```

### Python：从小事里收集灵感

```python
ideas = ["窗边的光", "散步时听到的声音", "一本读到一半的书"]

for index, idea in enumerate(ideas, start=1):
    print(f"{index:02d}. {idea}")
```

### JSON：一份容易阅读的配置

```json
{
  "title": "周末写作计划",
  "theme": "当前选择的主题",
  "readingMinutes": 6,
  "checklist": ["整理结构", "检查图片", "预览排版"]
}
```

长行测试：`a-very-long-file-name-for-checking-inline-code-wrapping-in-a-narrow-mobile-preview.md`。缩小窗口或打开公众号预览，观察长内容是否能合理换行。

你可以把这张图片替换成自己的照片，比较不同主题下的宽度、边距和圆角处理。

## 07 / 在不同出口，看同一篇文章

### 即时编辑

重点观察：标题层级是否清晰，引用是否舒适，列表缩进是否合适，代码是否容易阅读。试着用顶部工具栏把一个段落改成引用，再撤销，体验文字与结构之间的切换。

### 公众号预览

重点观察：表格是否太宽，长链接是否换行，图片是否完整，文字颜色和背景高亮是否保留。应用内预览是检查入口，最终仍要在公众号后台保存草稿并查看手机效果。

### PDF 导出

重点观察：页边距是否均衡，代码块是否被不自然地切开，图片是否落在合适的位置。如果希望每个大章节从新页开始，可以在导出设置中开启“按一级标题分页”。

## 尾声 / 写完之后，把生活还给生活

文章不必把所有样式都用一遍。这篇示例刻意放入了许多元素，是为了让你比较主题；真正写作时，通常只需要清楚的标题、自然的段落，以及少量必要的强调。

> 把该说的话说明白，把值得留住的细节留下来。
>
> 然后合上电脑，去经历下一篇文章。

### TypeScript：类型、泛型与错误处理

```typescript
type Article = {
  id: string;
  title: string;
  tags: string[];
  publishedAt: string | null;
};

async function request<T>(path: string): Promise<T> {
  const response = await fetch(path);
  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`);
  }
  return response.json() as Promise<T>;
}

const articles = await request<Article[]>("/api/articles");
const published = articles.filter(item => item.publishedAt !== null);
```

### SQL：查询与聚合

```sql
SELECT
    author_id,
    COUNT(*) AS article_count,
    MAX(published_at) AS latest_publish_time
FROM articles
WHERE status = 'published'
  AND published_at >= '2026-01-01'
GROUP BY author_id
HAVING COUNT(*) >= 3
ORDER BY article_count DESC
LIMIT 20;
```
